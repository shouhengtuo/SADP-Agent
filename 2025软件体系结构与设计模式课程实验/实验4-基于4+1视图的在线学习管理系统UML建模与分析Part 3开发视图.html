🧱 一、开发视图概述

🎯 目标与作用

开发视图（Development View），也称为模块视图，关注软件在开发环境下的静态组织结构。它描述了：

  • 源代码如何组织（目录结构、包/模块划分）
  • 各模块之间的依赖关系
  • 构建、测试、部署的单元

对于 OLMS 微服务系统，开发视图将重点展示每个微服务的内部代码结构，以及服务之间的依赖关系。

🔧 开发视图 vs 逻辑视图

逻辑视图关注“业务对象是什么”（如 Course、User 类）
开发视图关注“代码如何组织”（如 course-service/src/main/java/com/olms/course/）

逻辑视图是“业务语言”，开发视图是“工程语言”。一个逻辑类可能对应多个开发文件（.java, .xml, .yaml）。

📦 二、微服务模块划分原则

开发视图的基础是合理的微服务划分。我们遵循以下原则：

1
单一职责原则（SRP）： 每个微服务只负责一个核心业务领域（如课程服务只管课程）。
2
高内聚低耦合： 服务内部功能紧密相关，服务之间依赖最小化。
3
数据自治： 每个服务拥有自己的数据库，避免跨服务直接访问数据库。
4
团队对齐： 一个服务通常由一个小型开发团队负责（康威定律）。

🧩 三、包图建模：代码组织结构

🎯 设计目标

包图（Package Diagram）是开发视图的核心 UML 图，用于展示系统的模块化结构和依赖关系。

🔧 设计步骤

1
定义顶层包： 每个微服务作为一个顶层包。
2
定义内部子包： 每个微服务内部按分层架构组织（Controller/Service/Repository）。
3
标注依赖关系： 使用带箭头的虚线表示依赖（A → B 表示 A 依赖 B）。

📡 五、服务间通信机制

在微服务架构中，服务间通信是开发视图的重要组成部分。OLMS 系统采用两种主要通信方式：

1. 同步通信（REST API）

适用场景： 需要立即响应的操作（如创建课程时验证教师身份）
实现方式： 课程服务调用用户服务的 REST API
技术栈： Spring Cloud OpenFeign / RestTemplate 
// 课程服务中调用用户服务
@FeignClient(name = "user-service")
public interface UserServiceClient {
    @GetMapping("/users/{userId}")
    UserDTO getUserById(@PathVariable String userId);
    
    @GetMapping("/users/{userId}/role")
    String getUserRole(@PathVariable String userId);
}

2. 异步通信（消息队列）

适用场景： 非关键路径、解耦操作（如发送通知、记录日志）
实现方式： 课程服务发布“课程创建”事件，通知服务订阅该事件
技术栈： RabbitMQ / Kafka + Spring Cloud Stream 
// 课程服务发布事件
rabbitTemplate.convertAndSend("course.exchange", "course.created", courseEvent);

// 通知服务监听事件
@RabbitListener(queues = "notification.queue")
public void handleCourseCreated(CourseEvent event) {
    notificationService.sendNotification(
        "新课程上线: " + event.getCourseTitle(),
        event.getStudentIds()
    );
}
关键设计决策：
同步通信保证强一致性但增加耦合；异步通信提高可用性但引入最终一致性。OLMS 系统对核心业务（如选课）使用同步，对非核心（如通知）使用异步。

💡 给初学者的特别指导：如何学好开发视图？

1
理解“包” vs “类”：
包是代码的物理组织（文件夹），类是逻辑概念。一个包包含多个类。
2
掌握分层架构：
Controller（接收请求）→ Service（处理业务）→ Repository（操作数据）是标准模式。
3
依赖方向很重要：
依赖箭头从“使用者”指向“被使用者”。避免循环依赖（A 依赖 B，B 又依赖 A）。
4
同步 vs 异步：
需要立即结果用同步（REST），可延迟处理用异步（消息队列）。
记住： 开发视图是程序员的“地图”。地图画得好，团队开发才不会迷路。先画包图，再写代码！
