🌍 一、物理视图概述

🎯 目标与作用

物理视图（Physical View），也称为部署视图，描述软件系统如何部署到物理或虚拟硬件环境中。它关注：

  • 服务器、容器、网络设备等物理/虚拟节点
  • 软件组件（服务、数据库、中间件）在节点上的分布
  • 节点间的网络连接与通信方式
  • 高可用、负载均衡、容灾备份等运维策略

对于 OLMS 微服务系统，物理视图将展示其在云平台（如 Kubernetes）上的完整部署架构。

🔧 物理视图 vs 开发视图

开发视图关注“代码如何组织”（逻辑模块）
物理视图关注“代码运行在哪里”（物理/虚拟节点）

例如，开发视图中的“课程服务”包，在物理视图中可能部署为多个 Docker 容器实例，运行在 Kubernetes 集群的不同节点上。

☁️ 二、部署环境说明

OLMS 系统采用云原生架构，部署在 Kubernetes 集群中，具体环境如下：

1
基础设施： 公有云（如阿里云、华为云）或私有云（OpenStack）
2
容器平台： Kubernetes（K8s），负责容器编排、自动扩缩容、服务发现
3
镜像仓库： Harbor 或 Docker Hub，存储 Docker 镜像
4
网络模型： CNI（如 Calico），提供 Pod 间通信
5
存储方案： 本地 SSD + 云盘（用于数据库持久化）

🔗 六、五视图整合总结

4+1 视图不是孤立的，而是相互关联、协同工作的整体。下表总结了 OLMS 系统中五视图的关系：

视图 核心问题 驱动关系 OLMS 示例
场景视图 系统做什么？ → 驱动其他所有视图 “直播授课”用例
逻辑视图 功能如何组织？ ← 场景；→ 开发 Course、LiveStream 类设计
开发视图 代码如何组织？ ← 逻辑；→ 物理 live-service 微服务模块
进程视图 运行时如何交互？ ← 场景；← 逻辑 直播授课序列图
物理视图 部署到哪里？ ← 开发；← 进程 Kubernetes 部署架构
关键结论：
  • 场景视图是“需求源头”，其他视图都是对它的细化和实现
  • 逻辑视图和开发视图关注“静态结构”，进程视图和物理视图关注“动态行为”
  • 五视图共同构成完整的软件架构描述，缺一不可

💡 七、给初学者的学习路径建议

📌 推荐学习顺序

1
先学场景视图： 用例图 → 理解用户需求
2
再学逻辑视图： 类图/状态图 → 理解业务对象
3
接着学开发视图： 包图 → 理解代码组织
4
然后学进程视图： 序列图 → 理解运行时交互
5
最后学物理视图： 部署图 → 理解系统部署

✅ 实验成果要求

完整实验报告应包含：
  • Part 1：场景视图（用例图 + 用例描述）
  • Part 2：逻辑视图（类图 + 状态图 + 活动图）
  • Part 3：开发视图（包图 + 代码结构）
  • Part 4：进程视图（序列图 + 通信机制）
  • Part 5：物理视图（部署图 + 运维设计） + 五视图总结
