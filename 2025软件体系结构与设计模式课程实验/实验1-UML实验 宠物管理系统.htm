📘 一、PlantUML 快速入门（学生友好版）

💡 为什么学习 PlantUML？
PlantUML 是一种基于文本的 UML 建模工具，通过编写简单语法即可自动生成专业 UML 图形。无需拖拽、无需安装复杂软件，支持在线编辑、版本控制、团队协作，是敏捷开发和教学实验的理想选择！

✅ PlantUML 核心优势：

优势 说明
📝 文本驱动 用代码写图，易修改、易复用、易版本管理
🌐 在线可用 https://www.plantuml.com/plantuml 即开即用
🖼️ 自动绘图 输入文本 → 自动生成 PNG/SVG/PDF
🧩 支持所有UML图 用例图、类图、序列图、状态图等一应俱全

🧩 基础语法示例（快速上手）

1. 用例图（Use Case Diagram）

@startuml actor 主人 as Owner actor 兽医 as Vet actor 系统管理员 as Admin rectangle "智能宠物管理系统" { Owner --> (创建宠物档案) Owner --> (设置喂食计划) Owner --> (查看健康数据) Owner --> (接收异常提醒) Vet --> (查看宠物病历) Vet --> (提交诊断报告) Admin --> (管理用户权限) Admin --> (同步云端数据) } @enduml

2. 类图（Class Diagram）

@startuml class Pet { -petId: String -name: String -species: String -healthStatus: String +updateHealthData() } class Owner { -ownerId: String -name: String +addPet() +setFeedingPlan() } class FeedingPlan { -planId: String -time: DateTime -foodType: String +triggerReminder() } Pet "1" -- "1..*" Owner Owner "1" -- "0..*" FeedingPlan @enduml

3. 序列图（Sequence Diagram）——“设置喂食提醒”

@startuml actor 主人 participant "App界面" as UI participant "提醒服务" as AlertService participant "云数据库" as CloudDB 主人 -> UI: 点击“设置喂食提醒” UI -> AlertService: createReminder(time, food) AlertService -> CloudDB: saveReminder() CloudDB --> AlertService: success AlertService --> UI: 显示“设置成功” UI --> 主人: 提示设置完成 @enduml

4. 状态图（State Diagram）——宠物健康状态变迁

@startuml [*] --> 健康 健康 --> 亚健康: 连续3天活动量下降\n或进食异常 亚健康 --> 生病: 体温异常\n或兽医标记 生病 --> 康复: 治疗完成\n数据恢复正常 康复 --> 健康: 连续7天数据正常 亚健康 --> 健康: 数据恢复正常 生病 --> 亚健康: 初步治疗有效 健康 --> [*] @enduml

🖼️ 图2：类图 Class_SmartPet.puml

要求：至少8个类，体现关联

@startuml class Pet { -petId: String -name: String -species: String -birthDate: Date -healthStatus: String +updateStatus(newStatus: String) } class Owner { -ownerId: String -name: String -phone: String +addPet(pet: Pet) +setFeedingPlan(plan: FeedingPlan) } class FeedingPlan { -planId: String -scheduledTime: DateTime -foodType: String -isRecurring: Boolean +activateReminder() } class HealthMonitor { -sensorId: String -lastReading: Double -unit: String +collectData() +detectAnomaly() } class AlertService { -alertId: String -message: String -sentTime: DateTime +sendAlertToOwner() } class CloudSyncService { +syncDataToCloud() +fetchLatestData() } class VetRecord { -recordId: String -diagnosis: String -prescription: String -vetId: String } class SystemAdmin { -adminId: String +manageUserAccess() +triggerSync() } Owner "1" -- "0..*" Pet Owner "1" -- "0..*" FeedingPlan Pet "1" -- "1" HealthMonitor HealthMonitor --> AlertService : 异常时触发 Owner --> AlertService : 接收提醒 CloudSyncService ..> Pet : 同步数据 CloudSyncService ..> HealthMonitor : 同步数据 SystemAdmin --> CloudSyncService : 手动触发 VetRecord -- Pet @enduml
✅ 导出文件： Class_SmartPet.png

🖼️ 图3：序列图 Sequence_SetReminder.puml

描述：“主人设置喂食提醒”完整流程

@startuml title 设置喂食提醒流程 actor 主人 participant "手机App" as App participant "提醒服务" as ReminderService participant "数据库" as DB participant "推送服务" as PushService 主人 -> App: 选择宠物，设置喂食时间/食物 App -> ReminderService: createReminder(petId, time, food) ReminderService -> DB: 保存提醒记录 DB --> ReminderService: 保存成功 ReminderService -> PushService: 注册定时推送 PushService --> ReminderService: 注册成功 ReminderService --> App: 返回“设置成功” App --> 主人: 显示“✅ 喂食提醒已设置” note right of PushService 到时间后自动推送通知给主人 end note @enduml
✅ 导出文件： Sequence_SetReminder.png

💡 五、常见问题与提示

❓ Q1：我不会画类之间的关系怎么办？

✅ 记住口诀：
  • “拥有” → 实线实心菱形（组合）或实线空心菱形（聚合）
  • “使用” → 虚线箭头（依赖）
  • “是一种” → 实线空心三角（继承）
  • “知道” → 实线箭头（关联）

❓ Q2：状态图中的“触发条件”怎么写？

✅ 使用自然语言描述触发事件，例如：
健康 --> 亚健康: 连续3天进食量下降

❓ Q3：序列图中对象太多怎么办？

✅ 只保留核心参与对象（4~6个为佳），避免信息过载。非核心服务可合并或省略。

❓ Q4：导出的图太小/文字看不清？

✅ 在 PlantUML 在线编辑器中，在代码第一行加入：
@startuml skinparam dpi 300 skinparam defaultFontName 微软雅黑 skinparam defaultFontSize 14 ...
可提升清晰度和字体可读性。

📝 八、学生实验报告撰写要求

根据软件设计说明书标准格式撰写实验报告，要求结构完整、图文并茂、逻辑清晰、分析深入。

1. 报告基本结构要求

  1. 封面页：包含实验名称、课程名称、学生姓名、学号、班级、实验日期、指导教师（拓守恒教授）
  2. 目录：自动生成目录，包含各级标题和页码
  3. 引言/概述：简述实验目的、实验环境、实验工具（PlantUML、CodeArts）
  4. 需求分析：详细描述智能宠物管理系统的功能需求和非功能需求
  5. 系统设计：包含所有UML图及详细说明（重点部分）
  6. 实验过程：记录实验步骤、遇到的问题及解决方案
  7. 实验结果：展示最终成果，分析设计合理性
  8. 总结与反思：实验收获、不足之处、改进建议
  9. 参考文献：列出参考的资料、工具文档等

2. 图文规范要求

  • 所有图表必须有图题（Figure Caption）和图的解释说明
  • 图题格式：图X-Y 图表名称（如：图3-1 用例图）
  • 图题位于图下方，居中，使用五号宋体加粗
  • 图的解释说明位于图题下方，使用小五号宋体，解释图中关键元素、设计思路和逻辑关系
  • 图片清晰度不低于300dpi，大小适中，布局合理
  • 所有UML图必须与PlantUML源代码对应，确保一致性
示例：图3-1 智能宠物管理系统用例图
本用例图展示了系统三大角色（主人、兽医、系统管理员）与八个核心用例的交互关系。主人可执行宠物档案管理、喂食计划设置、健康数据查看和异常提醒接收；兽医负责病历访问和诊断报告录入；系统管理员管理用户权限和数据同步。各角色职责分明，用例覆盖系统核心功能。

3. 内容深度要求

  • 用例图：不仅要展示角色与用例关系，还需说明各用例的简要描述和前置/后置条件
  • 类图：详细说明每个类的属性和方法设计理由，类间关系的业务含义
  • 序列图：分析消息传递的时序逻辑，说明各对象的职责和协作方式
  • 状态图：解释状态变迁的触发条件和业务规则，说明状态机设计的合理性
  • 每个图的解释说明不少于150字，需体现个人思考和理解

4. 格式与排版要求

  • 使用Word或PDF格式提交，文件命名：学号_姓名_智能宠物管理系统UML设计报告.docx/pdf
  • 正文使用小四号宋体，1.5倍行距
  • 一级标题三号黑体，二级标题四号黑体，三级标题小四号黑体
  • 页边距：上2.54cm，下2.54cm，左3.17cm，右3.17cm
  • 页码位于页面底端居中
  • 参考文献格式规范，不少于3篇参考文献

5. 评分细则（报告部分）

评分项 分值 评分标准
结构完整性 20% 报告结构完整，包含所有要求的部分

内容深度 30% 对UML图的解释深入，体现个人理解和思考
格式规范性 20% 符合排版要求，无格式错误
