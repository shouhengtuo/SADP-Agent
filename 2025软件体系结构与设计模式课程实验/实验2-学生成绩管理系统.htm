📘 一、PlantUML 快速入门（学生友好版）

💡 为什么学习 PlantUML？
PlantUML 是一种基于文本的 UML 建模工具，通过编写简单语法即可自动生成专业 UML 图形。无需拖拽、无需安装复杂软件，支持在线编辑、版本控制、团队协作，是敏捷开发和教学实验的理想选择！

✅ PlantUML 核心优势：

优势 说明
📝 文本驱动 用代码写图，易修改、易复用、易版本管理
🌐 在线可用 https://www.plantuml.com/plantuml 即开即用
🖼️ 自动绘图 输入文本 → 自动生成 PNG/SVG/PDF
🧩 支持所有UML图 用例图、类图、序列图、状态图、活动图、构件图、部署图等一应俱全

3. 序列图（Sequence Diagram）——“教师录入成绩”

@startuml actor 教师 participant "系统界面" as UI participant "成绩服务" as GradeService participant "数据库" as DB 教师 -> UI: 选择课程和学生 UI -> GradeService: submitGrade(studentId, courseId, score) GradeService -> DB: saveGrade() DB --> GradeService: success GradeService --> UI: 返回“录入成功” UI --> 教师: 显示“✅ 成绩已录入” @enduml

4. 状态图（State Diagram）——成绩状态变迁

💡 五、常见问题与提示

❓ Q1：我不会画类之间的关系怎么办？

✅ 记住口诀：
  • “拥有” → 实线实心菱形（组合）或实线空心菱形（聚合）
  • “使用” → 虚线箭头（依赖）
  • “是一种” → 实线空心三角（继承）
  • “知道” → 实线箭头（关联）
  • “实现接口” → 虚线空心三角（实现）

❓ Q2：状态图中的“触发条件”怎么写？

✅ 使用自然语言描述触发事件，例如：
待录入 --> 已录入: 教师录入分数

❓ Q3：序列图中对象太多怎么办？

✅ 只保留核心参与对象（4~6个为佳），避免信息过载。非核心服务可合并或省略。

❓ Q4：导出的图太小/文字看不清？

✅ 在 PlantUML 在线编辑器中，在代码第一行加入：
@startuml skinparam dpi 300 skinparam defaultFontName 微软雅黑 skinparam defaultFontSize 14 ...
可提升清晰度和字体可读性。

❓ Q5：构件图和部署图有什么区别？

✅ 构件图 关注的是软件的逻辑组织和依赖（软件层面）；部署图 关注的是软件如何部署到硬件节点上（物理层面）。

📝 八、学生实验报告撰写要求

根据软件设计说明书标准格式撰写实验报告，要求结构完整、图文并茂、逻辑清晰、分析深入。本次实验要求报告中包含所有7个UML图及其详细分析。

1. 报告基本结构要求

  1. 封面页：包含实验名称、课程名称、学生姓名、学号、班级、实验日期、指导教师（拓守恒教授）
  2. 目录：自动生成目录，包含各级标题和页码
  3. 引言/概述：简述实验目的、实验环境、实验工具（PlantUML、CodeArts）
  4. 需求分析：详细描述学生成绩管理系统的功能需求和非功能需求
  5. 系统设计：包含所有UML图及详细说明（重点部分，需包含用例图、增强类图、泳道序列图、活动图、状态图、构件图、部署图）
  6. 实验过程：记录实验步骤、遇到的问题及解决方案
  7. 实验结果：展示最终成果，分析设计合理性
  8. 总结与反思：实验收获、不足之处、改进建议
  9. 参考文献：列出参考的资料、工具文档等

2. 图文规范要求

  • 所有图表必须有图题（Figure Caption）和图的解释说明
  • 图题格式：图X-Y 图表名称（如：图3-1 用例图）
  • 图题位于图下方，居中，使用五号宋体加粗
  • 图的解释说明位于图题下方，使用小五号宋体，解释图中关键元素、设计思路和逻辑关系
  • 图片清晰度不低于300dpi，大小适中，布局合理
  • 所有UML图必须与PlantUML源代码对应，确保一致性
示例：图3-1 学生成绩管理系统用例图
本用例图展示了系统三大角色（学生、教师、管理员）与十个核心用例的交互关系。学生可执行成绩查询、排名查看等操作；教师负责成绩的录入与修改，并可查看班级统计；管理员则负责系统的用户和课程信息管理。各角色职责分明，用例覆盖了系统的核心业务功能。

3. 内容深度要求

  • 用例图：不仅要展示角色与用例关系，还需说明各用例的简要描述和前置/后置条件
  • 增强类图：详细说明每个类的属性和方法设计理由，类间关系的业务含义（特别是继承、实现、聚合、组合）
  • 泳道序列图：分析跨组件的交互流程，说明各组件的职责和协作方式
  • 活动图：分析业务流程的步骤、决策点、并发处理和对象流
  • 状态图：解释状态变迁的触发条件和业务规则，说明状态机设计的合理性
  • 构件图：解释系统模块的划分、接口定义和依赖关系
  • 部署图：解释系统的物理部署结构和硬件/软件映射关系
  • 每个图的解释说明不少于200字，需体现个人思考和理解

4. 格式与排版要求

  • 使用Word或PDF格式提交，文件命名：学号_姓名_学生成绩管理系统UML设计报告.docx/pdf
  • 正文使用小四号宋体，1.5倍行距
  • 一级标题三号黑体，二级标题四号黑体，三级标题小四号黑体
  • 页边距：上2.54cm，下2.54cm，左3.17cm，右3.17cm
  • 页码位于页面底端居中
  • 参考文献格式规范，不少于3篇参考文献
