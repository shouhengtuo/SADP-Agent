⚡ 一、进程视图概述

🎯 目标与作用

进程视图（Process View）关注系统的运行时行为，描述系统在运行过程中对象、进程、线程之间的动态交互、并发控制和通信机制。它主要解决系统的非功能性需求，如性能、吞吐量、响应时间、可靠性等。

对于 OLMS 微服务系统，进程视图将重点展示：

  • 关键业务流程的跨服务调用顺序（如直播授课、作业提交）
  • 同步 vs 异步通信机制（REST vs 消息队列）
  • 并发处理策略（线程池、连接池、限流熔断）

🔧 进程视图 vs 逻辑视图

逻辑视图关注“对象有什么方法”（静态结构）
进程视图关注“方法如何被调用、何时被调用”（动态执行）

例如，逻辑视图定义了 CourseService.createCourse() 方法，而进程视图展示该方法在“创建课程”流程中何时被调用、由谁调用、是否异步。

🔍 二、关键业务流程识别

进程视图应聚焦于对系统性能、可靠性影响最大的核心流程。我们选择以下三个关键流程进行建模：

1
直播授课流程： 高并发、低延迟、实时性要求高
2
作业提交与批改流程： 涉及数据一致性、事务处理
3
学习行为跟踪流程： 高频写入、异步处理、最终一致性

📈 三、序列图建模：跨服务交互

🎯 设计目标

序列图（Sequence Diagram）是进程视图的核心 UML 图，用于描述对象之间按时间顺序的消息传递过程。

📡 四、通信机制详解

微服务间的通信是进程视图的核心。OLMS 系统采用两种主要通信模式：

1. 同步通信（Request/Response）

适用场景： 需要立即响应的操作（如登录验证、课程创建）
协议： HTTP/HTTPS + REST/JSON
技术栈： Spring Cloud OpenFeign / WebClient
超时设置： 通常 1-3 秒，避免长时间阻塞 
// 课程服务调用用户服务（同步）
@FeignClient(name = "user-service", fallback = UserClientFallback.class)
public interface UserClient {
    @GetMapping("/users/{id}/role")
    String getUserRole(@PathVariable String id);
}

// 熔断降级
@Component
public class UserClientFallback implements UserClient {
    public String getUserRole(String id) {
        return "unknown"; // 降级返回默认值
    }
}

2. 异步通信（Event-Driven）

适用场景： 非关键路径、解耦操作（如发送通知、记录日志）
协议： AMQP / Kafka Protocol
技术栈： RabbitMQ / Apache Kafka + Spring Cloud Stream
消息可靠性： 持久化、ACK机制、死信队列 
// 发布事件
@Service
public class AssignmentService {
    @Autowired
    private StreamBridge streamBridge;
    
    public void submitAssignment(...) {
        // ... 保存作业
        streamBridge.send("assignment-out-0", 
            MessageBuilder.withPayload(new AssignmentSubmittedEvent(submissionId))
                         .build());
    }
}

// 订阅事件
@StreamListener("notification-in-0")
public void handleAssignmentSubmitted(AssignmentSubmittedEvent event) {
    notificationService.sendToTeacher("新作业待批改", event.getSubmissionId());
}
关键设计原则：
  • 同步用于“写”和强一致性场景（如创建、更新）
  • 异步用于“读”和最终一致性场景（如通知、统计）
  • 永远不要在同步链路过长（避免 A→B→C→D 的级联调用）

⚡ 五、并发与性能设计

进程视图必须考虑系统的并发处理能力。OLMS 系统采用以下策略：

1. 线程池管理

1
Web 容器线程池： Tomcat 默认 200 线程，根据负载调整
2
异步任务线程池： 使用 @Async 处理耗时操作（如文件解析） 
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean("taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(10);
        executor.setMaxPoolSize(50);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("Async-");
        executor.initialize();
        return executor;
    }
}

2. 连接池优化

1
数据库连接池： HikariCP，最大连接数 20-50
2
HTTP 连接池： Feign + Apache HttpClient，复用连接

3. 限流与熔断

1
API 网关限流： 基于令牌桶算法，限制每秒请求数
2
服务熔断： 使用 Resilience4j，失败率 > 50% 时自动熔断 
// 熔断配置
resilience4j.circuitbreaker:
  instances:
    userService:
      failureRateThreshold: 50
      waitDurationInOpenState: 5000
      slidingWindowSize: 10

💡 给初学者的特别指导：如何学好进程视图？

1
关注“时间顺序”：
序列图的纵轴是时间，消息从上到下依次发生。先画主流程，再画异常流程。
2
区分同步与异步：
同步消息用实线箭头（→），异步用虚线（--→）。异步不等待返回。
3
不要忽略非功能性需求：
性能、可靠性、可扩展性是进程视图的核心，不是可有可无。
4
从场景出发：
先想“直播时会发生什么？”，再画图，而不是先画图再想场景。
记住： 进程视图是系统的“动态骨架”。它告诉你系统在运行时“如何呼吸、如何跳动”。理解它，才能设计出高性能、高可用的系统！
