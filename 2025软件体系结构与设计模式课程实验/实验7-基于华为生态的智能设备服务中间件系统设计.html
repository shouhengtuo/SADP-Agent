基于华为生态的智能设备服务中间件系统设计
—— 设计模式综合实验

本实验要求基于华为云IoT平台,CodeArts或HarmonyOS设备协同场景，设计并实现一个支持多种设计模式的中间件系统。以下为详细设计思路与类图规范，需据此完成代码实现与实验报告撰写。

1. 单例模式（Singleton）

应用场景

系统全局配置管理器（SystemConfig）与设备注册中心（DeviceRegistry）在整个应用生命周期中仅需一个实例，且需线程安全（适配华为云多线程容器环境）。

设计要点

  • 使用双重检查锁（DCL）或静态内部类实现懒加载；
  • 禁止外部通过构造函数创建实例；
  • 考虑序列化/反序列化安全（可选高阶要求）。

PlantUML 类图

@startuml
class SystemConfig {
  - static instance: SystemConfig
  - SystemConfig()
  + static getInstance(): SystemConfig
}

  线程安全单例
  懒加载或饿汉式

@enduml

2. 适配器模式（Adapter）

应用场景

系统需接入不同厂商设备（如厂商A提供 start()/readData()，厂商B提供 powerOn()/getData()），但对外暴露统一接口 IDevice（connect(), fetchData()）。

设计要点

  • 定义统一设备接口 IDevice；
  • 为每类异构设备实现一个适配器类；
  • 适配器持有目标设备实例并转换调用。

PlantUML 类图

@startuml
interface IDevice {
  + connect()
  + fetchData()
}

class VendorADevice {
  + start()
  + readData()
}

class VendorBDevice {
  + powerOn()
  + getData()
}

class AdapterA {
  - vendor: VendorADevice
  + connect()
  + fetchData()
}

class AdapterB {
  - vendor: VendorBDevice
  + connect()
  + fetchData()
}

IDevice <|-- AdapterA
IDevice <|-- AdapterB
AdapterA --> VendorADevice : uses
AdapterB --> VendorBDevice : uses
@enduml

3. 观察者模式（Observer）

应用场景

当设备状态变化（如门锁解锁、传感器超阈值），需通知日志模块、告警服务、UI界面等多个观察者。

设计要点

  • 定义 DeviceSubject（被观察者）与 IObserver 接口；
  • 支持动态注册/注销观察者；
  • 通知时传递事件上下文（如设备ID、状态值）。

PlantUML 类图

@startuml
interface IObserver {
  + update(event: DeviceEvent)
}

class DeviceSubject {
  - observers: List
  + attach(o: IObserver)
  + detach(o: IObserver)
  + notify(event: DeviceEvent)
}

class UILogger
class AlarmService
class DataRecorder

DeviceSubject --> IObserver : notifies
IObserver <|-- UILogger
IObserver <|-- AlarmService
IObserver <|-- DataRecorder
@enduml

4. 装饰模式（Decorator）

应用场景

设备数据发送功能需动态叠加加密、压缩、添加时间戳等增强行为，组合方式在运行时确定。

设计要点

  • 定义 IDataSender 接口；
  • 提供基础实现 BasicSender；
  • 所有装饰器继承 DataSenderDecorator 并持有 IDataSender 引用。

PlantUML 类图

@startuml
interface IDataSender {
  + send(data: String)
}

class BasicSender {
  + send(data: String)
}

abstract class DataSenderDecorator {
  - sender: IDataSender
  + send(data: String)
}

class EncryptionDecorator {
  + send(data: String)
}

class CompressionDecorator {
  + send(data: String)
}

class TimestampDecorator {
  + send(data: String)
}

IDataSender <|-- BasicSender
IDataSender <|-- DataSenderDecorator
DataSenderDecorator <|-- EncryptionDecorator
DataSenderDecorator <|-- CompressionDecorator
DataSenderDecorator <|-- TimestampDecorator
DataSenderDecorator --> IDataSender : wraps
@enduml

5. 代理模式（Proxy）

应用场景

调用华为云AI服务（如图像识别）前，需进行权限校验、访问频率控制、日志记录等，避免直接暴露真实服务。

设计要点

  • 代理类与真实服务实现相同接口；
  • 代理在调用前后插入控制逻辑；
  • 可结合单例管理连接池（高阶）。

PlantUML 类图

@startuml
interface IHuaweiAIService {
  + analyze(image: byte[]): AnalysisResult
}

class HuaweiAIService {
  + analyze(image: byte[]): AnalysisResult
}

class HuaweiAIServiceProxy {
  - realService: HuaweiAIService
  + analyze(image: byte[]): AnalysisResult
}

IHuaweiAIService <|-- HuaweiAIService
IHuaweiAIService <|-- HuaweiAIServiceProxy
HuaweiAIServiceProxy --> HuaweiAIService : delegates to
@enduml

6. 桥接模式（Bridge）

应用场景

设备类型（灯、传感器、门锁）与通信平台（Wi-Fi、蓝牙、Zigbee）两个维度独立变化，避免类爆炸。

设计要点

  • 将抽象部分（设备类型）与实现部分（平台）分离；
  • 通过组合而非继承连接两个维度；
  • 支持运行时动态切换平台。

PlantUML 类图

@startuml
abstract class AbstractDevice {
  - platform: DevicePlatform
  + operate()
}

interface DevicePlatform {
  + sendData(data: String)
}

AbstractDevice <|-- LockDevice

DevicePlatform <|-- BLEPlatform
DevicePlatform <|-- ZigbeePlatform

AbstractDevice --> DevicePlatform : uses
@enduml
